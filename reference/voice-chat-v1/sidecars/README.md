# Smith next voice sidecars (T3)

**Implemented source:** offline CPU STT/TTS adapters, bounded ASGI APIs, packaging and fake tests for [the approved voice plan](../../docs/plans/LOCAL-SMITH-NEXT-VOICE-CHAT.md). This is not deployed-host, actual speech-quality, model compatibility or container-network evidence. Parent T4 owns canonical documentation, Dagger integration and fresh independent review. Policy: [AGENTS](../../AGENTS.md), [architecture](../../docs/ARCHITECTURE.md), [approval boundaries](../../docs/PROCESS.md#approval-boundaries).

## Parent quality integration

From the repository root, without installing any dependencies:

```sh
PYTHONDONTWRITEBYTECODE=1 python3.12 -m unittest discover -s next/sidecars/tests -v
```

**No dev requirements or pytest needed.** `unittest` calls ASGI directly with fake engines, streamed request events and in-memory WAV fixtures; no listening sockets, providers, microphones or containers. Three optional numeric tests skip without NumPy. Run the same command in a Python 3.12 runtime-dependency environment to include them. These use synthetic arrays and mock inference, not real weights.

`requirements.txt` pins the complete runtime dependency closure without extras, taken from the existing Python 3.12 sidecar venv metadata. Both original environments pass `pip check`; installed loader signatures were inspected. Uvicorn uses only its base h11/asyncio implementation. No framework or multipart dependency is needed. This metadata-derived pin set is not a hash-verified supply-chain lock, nor evidence of a clean combined installation/image build. Docker image tag and Debian native packages are not digest/version locked. Parent should retain those limitations in build evidence. Building the image requires deliberately authorized package/image registry access, but never downloads models.

## Frozen HTTP contract

- STT: loopback host port **4890**, internal container port 4890.
- TTS: loopback host port **4891**, internal container port 4891.
- `GET /v1/health` always returns HTTP 200 JSON `{schema_version:1,service:"smith-next-stt"|"smith-next-tts",ready,model,voices,error_code}`. Model is a fixed format identifier (`whisper-ctranslate2` or `kokoro-onnx`), not a host path/model provenance claim. Missing/invalid weights: ready false, model null, voices empty, safe error code. Docker health is unhealthy while not ready; the process remains available for factual health. Repair then deliberately restart, not automatic reload/download.
- STT `POST /v1/transcribe`, `Content-Type: audio/wav`: raw complete RIFF/WAVE, PCM format 1, mono, 16000 Hz, 16-bit little endian, nonempty, <=60 seconds, <=2 MiB including headers. No multipart, JSON audio, uploaded paths or compressed audio. Returns `{schema_version:1,service:"smith-next-stt",text,language,duration_ms}`; duration is derived from validated input frames (integer milliseconds).
- TTS `POST /v1/speak`, `Content-Type: application/json`: exactly `{schema_version:1,text,voice}`. Reject unknown/duplicate fields, unsupported schema, nonstrings, empty/blank text, invalid Unicode, text >4096 UTF-8 bytes, and unobserved voice. No silent text truncation. Returns raw `audio/wav`, mono 24000 Hz PCM16, <=60 seconds and <=2,880,044 bytes. Overlong synthesis fails rather than truncates. No fake waveform fallback.
- Requests have a **10-second total streamed-body deadline**. STT cap 2 MiB; TTS JSON cap 32 KiB to allow escaped 4 KiB text. Content-Length is never used to authorize allocation. Encoded/compressed bodies are rejected. Output transcription text <=64 KiB. Replies use `Cache-Control: no-store`.
- One active body/inference per process; no queue. A concurrent request gets **409 BUSY** immediately, before reading its body. Health stays responsive. A caller timeout/disconnect does not promise native inference cancellation; the process remains busy until that worker exits. Parent uses its finite provider budgets and must not retry automatically. Resource limits are containment, not hard per-inference wall-clock cancellation.
- Error JSON: `{schema_version:1,service,error:{code,message:"Speech request could not be completed."}}`. Codes include `MODEL_MISSING`, `MODEL_LOAD_FAILED`, `VOICES_MISSING`, `MODEL_NOT_READY` (503), `BUSY` (409), `REQUEST_TOO_LARGE` (413), `UNSUPPORTED_MEDIA_TYPE` (415), `INVALID_AUDIO`, `INVALID_REQUEST`, `UNKNOWN_VOICE` (400), `REQUEST_TIMEOUT` (408), `OUTPUT_TOO_LARGE` (502), `INFERENCE_FAILED` (500/502), `NOT_FOUND` (404), `METHOD_NOT_ALLOWED` (405). No exception messages or model paths. HTTP error connections close rather than consume unlimited remaining bodies.

## Manual model provisioning — operator later, not agent execution

No build/start/inference pulls weights. HF offline/telemetry flags are set before model imports. Whisper uses **CPU/int8**, two threads, one worker and `local_files_only=True`; required tokenizer prevents the library's pretrained-tokenizer fallback. Kokoro uses an explicit **CPUExecutionProvider** ONNX session, two intra-op threads, one inter-op thread, and the real mounted voice archive. Neither adapter performs startup inference.

Provision only after separate operator approval. Choose a trusted source, review model/license terms and verify published checksums/provenance. Any optional download is an explicit operator action outside these services, with its own internet and persistent-disk effects. No download commands are run or supplied as automatic setup. Do not mount Hugging Face's entire cache, home directories or a broad model collection.

1. **Whisper:** supply one self-contained **CTranslate2-converted Whisper** directory compatible with faster-whisper/CTranslate2 (not PyTorch `.pt`, safetensors-only, GGUF, ONNX, or a Hugging Face cache pointer). For the default 2 GiB CPU cap, use a tiny/base-family model, not large. Files at its root must include exactly named `model.bin`, `config.json`, `tokenizer.json`, and `preprocessor_config.json`; retain any converter-produced vocabulary files (commonly `vocabulary.json`/`vocabulary.txt`) alongside them. Preserve the complete converted artifact. `config.json` describes the native model, `tokenizer.json` is the tokenizer export and `preprocessor_config.json` the matching audio feature configuration. The mounted root maps to `/models/whisper`. Missing required files is `MODEL_MISSING`; corrupt/incompatible models is `MODEL_LOAD_FAILED`.
2. **Kokoro:** supply one directory with **`kokoro-v1.0.onnx`** (Kokoro v1.0 ONNX export compatible with kokoro-onnx 0.6.1) and its matching **`voices-v1.0.bin`**. Despite `.bin`, the latter is a NumPy-loadable named voice archive, not an audio recording, JSON voice list or arbitrary raw binary. Preserve upstream names and matching versions; do not just rename unrelated models. This root maps to `/models/kokoro`. Native espeak-ng libraries/data are installed in the image. Only English `af_`, `am_`, `bf_`, `bm_` keys actually present in the archive are advertised; American keys synthesize with `en-us`, British with `en-gb`. No hard-coded default voice. An archive without usable English voices reports `VOICES_MISSING`. Other language support is not claimed by this slice.
3. The existing host directories/files must be traversable/readable by numeric container UID/GID **10001:10001**. The operator supplies absolute, narrow paths using **`SMITH_STT_MODEL_DIR`** and **`SMITH_TTS_MODEL_DIR`**; do not commit real paths in `.env` or documentation. The models must not depend on symlinks outside their narrow mounted directories.
4. Compose requires both variables via `${...:?}` and long bind syntax with **`create_host_path: false`**; it never creates a missing host model directory. An existing empty directory permits the service to start not-ready, but nonexistent directories fail container creation. Do not broaden mounts to make startup succeed.
5. In a separately approved operator deployment, review `compose.yaml` and render its config privately (rendering reveals chosen host paths). Build and start explicitly using `docker compose -f next/sidecars/compose.yaml build` then `docker compose -f next/sidecars/compose.yaml up -d`. These commands are instructions only and have **not** been executed by the agent. They consume image/package network and disk during build, then container resources. Restart policy is `no`; no autorun or daemon/service registration. Keep normal Smith/Ollama lifecycle separate.
6. Check `/v1/health` on each numeric loopback port. Ready means model initialization completed, not speech inference verified. Real recording/inference/playback smoke is a separate approved operator step. Repair failures through narrow model artifacts, not network/fake fallback or permissions expansion.

## Packaging boundaries and residual evidence

Separate `internal: true` networks; loopback-only published ports; no host network, Docker socket, home, device/audio, credential or daemon mounts. Containers are nonroot/read-only, drop all capabilities, set no-new-privileges, bound CPUs/memory/PIDs and a 64 MiB noexec/nosuid/nodev tmpfs. Application stores no audio/text on disk. Access/Python/native runtime logging is suppressed; only a fixed startup-failure message can reach stdout, and Docker logging is disabled. Health checks return status only. This deliberately trades tracebacks for safe codes.

Internal networking is not a complete host air gap and does not authenticate the trusted local operator. Docker/host firewall and actual loopback publication need independent deployment review. Container builds, healthcheck execution in a built image, dependency registry reproducibility, real weight initialization/speech quality and network-denied real inference are **not validated** by the fake tests. No normal-host container/provider/microphone operation is authorized by this source change.
