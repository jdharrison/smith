# Smith client

**Implemented in source:** the Linux-only Core loader → Setup/Home shell retains the schema-v1 control contract in [LOCAL-SMITH-NEXT-DEBUG-BOOT](../../docs/plans/LOCAL-SMITH-NEXT-DEBUG-BOOT.md). Home now hosts editable text/voice chat; LLM/Services provide explicit asynchronous local model/voice inventory and configuration through the separate [frozen application contract](../../docs/plans/LOCAL-SMITH-NEXT-VOICE-CHAT.md). Core Boot/Refresh remain inspection-only. App attachment reads saved state, not provider inventory. Nothing implicitly installs, starts, downloads, sends a draft, or plays restored audio.

Ready Home requires an affirmative helper result, installed binary/unit, running service, verified ready bridge and `setup_complete=true`. On a returning launch, installed binary/unit plus authoritative persisted `setup_complete=true`, resolved effect paths and no runtime/bridge identity conflict also route to **Home repair**, even when the service is stopped or unavailable. This is not readiness: the UI explicitly labels repair and the current status, with explicit Start for a safely observed stopped service and read-only Refresh. A failed control result can retain those independently validated completion facts but grants no action authority. A previously observed completion is remembered only within the desktop session during later unverified outages. Reopening reads authoritative service state again; the client does not invent durable completion.

```text
lib/main.dart          Minimal loader, status, setup and confirmation UI
lib/boot_controller.dart Injectable serialized lifecycle controller
lib/control_api.dart   Strict typed observation/prepare/apply contract
lib/native_control.dart Validated, bounded native helper adapter
lib/app_api.dart        Injectable app envelope API and 4 MiB stdin executor
lib/voice_chat.dart     Correlated one-job controller, composer and settings
lib/audio.dart          Bounded native capture/playback and private transient WAVs
linux/                 Flutter Linux runner (unchanged)
test/                  Fake API/process, protocol, lifecycle and layout tests
scripts/               Native test and paired-bundle build tasks
pubspec.yaml / pubspec.lock
```

`test/` is a peer of `lib/` and `linux/`. Run `flutter pub get --enforce-lockfile`, then `sh scripts/test.sh` (formatting, analysis and tests) or `sh scripts/build.sh ../service/target/release/smith-service` after building the service. `make client/build` from `next/` builds the paired bundle through Dagger.

## Helper and consent boundary

The default helper is `<actual desktop executable directory>/smith_backend/smith-service`. Developer runs may explicitly select an absolute path with the compile-time Dart define `SMITH_SERVICE_EXECUTABLE`, for example `flutter run -d linux --dart-define=SMITH_SERVICE_EXECUTABLE=/absolute/developer/path/smith-service`. This is an intentional graphical launch, not a test command. Relative overrides fail closed. No PATH/cwd search, shell, or detached fallback is used.

Before execution, the adapter rejects non-Linux, non-canonical/symlink/non-regular paths, group/world-writable executable paths or ancestors, non-executable files and non-x86_64 ELF headers. These are local safety checks, not cryptographic artifact authentication or a hostile same-UID defense. The helper independently validates installed paths, manager/peer identity and approved snapshots.

Each control invocation uses `Process.start` with an argument list and `runInShell=false`. Runtime is bounded to 45 seconds including validation/launch/output observation, accommodating Rust composite applies with up to three ten-second manager budgets and bounded socket checks; combined captured stdout/stderr is bounded to 16 KiB. Cleanup sends TERM only to the captured short-lived helper, continues bounded output draining, and allows up to 11 seconds for cooperative manager-command cleanup. If the helper has not exited, it escalates to KILL and waits up to one further second for confirmed exit. Concurrent cleanup requests share one sequence. Unverified cleanup retains captured ownership and blocks adapter reuse. The 45-second operation budget is separate from this bounded cleanup grace. Late launch results are cleaned, never adopted as a daemon. Stderr is not interpreted as status or displayed as an untrusted CLI diagnosis.

Install binary, Register service, Start service and Finish setup are distinct actions. Each runs `prepare --action <action>`, shows its exact description and four paths, and waits for Cancel/Confirm. Cancel never applies. Confirm runs only `apply --action <same-action> --approval <prepared-token>`; the helper must freshly revalidate the binding. Busy/duplicate actions are blocked, failures are visible with read-only Refresh, and disposal ignores stale results. For an installed, stopped binary/unit, both Start and Register service are offered because schema v1 does not separately expose manager loaded/not-found facts. Fresh Rust preparation permits Start only for a safely loaded unit, or a separately consented registration/reload retry for manager not-found or an exact owned installed unit with a safe stopped runtime and pending reload; a rejected prepare never opens confirmation or applies. No automatic reload retry occurs. Unknown/conflicting states do not imply readiness.

Structured `ok=false` preflight replies may have empty effect path strings. Their factual message/error are retained, but they provide no actionable proposal. Successful replies and successful preparations still require all four absolute, nonempty paths, and successful preparations also require a nonempty approval token. Malformed identities, types and status values remain rejected.

Timeout/cancellation is an **unknown outcome**, not rollback: an already accepted manager job or persisted write may remain. The controller invalidates readiness for unknown outcomes and requires a fresh read-only Refresh before a new action, which still needs fresh preparation and confirmation. Helper exit alone does not prove manager-descendant cleanup. Rust's cooperative cancellation owns manager-group cleanup; its parent-death protection covers only the direct manager child after abrupt helper death, not a forked descendant group.

Closing/disposal does **not** stop the persistent service. It cancels captured transient Core/app helpers, desktop audio children and further polling only; already-authorized service work may continue. These actions do not enable login autostart or lingering. This client has no Stop/uninstall controls.

## Validation boundary

Unit/widget tests inject `FakeControlApi` and fake helper processes. No tests launch the desktop, invoke a real manager, or mutate installed host service state. `sh scripts/test.sh` retains the existing format → analyze → test quality flow. No extra dependencies are needed. The fake-process-only constructor permits positive finite operation/grace/exit-confirmation budgets to keep cleanup tests fast; the production default remains 45 seconds. Coverage includes a simulated apply lasting longer than the former 15-second limit and bounded timeout cleanup.

`test/rust_socket_integration_test.dart` adds one isolated real Rust↔Dart Unix-socket test. Native direct tests skip it with an explicit reason only when `SMITH_TEST_SERVICE` is absent/empty; a supplied invalid path fails. Parent Dagger supplies the explicit compiled executable path for `make test`. To run directly with an existing build, set `SMITH_TEST_SERVICE` to its absolute path when invoking `sh scripts/test.sh` or `flutter test --no-pub test/rust_socket_integration_test.dart`.

The test copies that binary into a private temporary fixture, sets exact 0755 permissions and verifies effective-user ownership and one link. All data/config/runtime directories are private 0700. It starts only captured foreground `serve` children with explicit roots, closed stdin, bounded 16 KiB output and a 15-second watchdog; there are no `inspect`/`prepare`/`apply`/systemctl calls. Direct Dart Unix sockets use two-second I/O deadlines and 4096-byte newline JSON frames to verify identity/PID, initial false, explicit completion, socket detach survival, graceful SIGTERM, and persisted true after restart. Final cleanup confirms every captured child exited before removing temporary data. This bypasses manager integration deliberately and does not establish installed-host behavior.

Build output is `build/`; explicit Dagger artifact exports go in `dist/`. No Dagger dependency is bundled into the app. Dagger builds include the compatible helper at `smith_backend/smith-service`; `make client/run` prepares a safely copied native development helper. Real installed-host close/reopen validation remains a separate integration gate; fake tests and bundle builds do not establish it.

## Linux icon

The user-provided icon is tracked at `linux/runner/resources/smith.png` and embedded as a GLib resource in the runner, so GTK window-icon loading does not depend on the source tree or an external file. `glib-compile-resources` is a builder requirement supplied by the GTK/GLib development tooling, not a recipient dependency.

The bundle also includes desktop integration inputs under `share/applications/` and `share/pixmaps/`, matching the existing application ID. These are not installed or registered on the host by building. GNOME/Wayland dock and application-launcher icons generally require installed desktop integration; GTK's window icon alone is not a guarantee there. The future installer must register the assets and bind the launcher to the installed executable.

## Application and audio boundary

`NativeAppApi` sends one schema-v1 `app` request with a 32-lowercase-hex call ID via stdin to the same validated native helper, with argv exactly `['app']`. Prompts/audio never enter argv. App payloads are bounded to 4 MiB excluding newline; Core's existing combined 16 KiB output cap is unchanged. The helper retains its 45-second exchange deadline and captured-child cleanup. Replies require service/protocol/schema/PID/instance/call correlation; malformed or uncertain acknowledgements remain query-only, never automatic resend.

`ChatController` polls one admitted operation with a finite 210-second budget and retains uncertain request identity for explicit synchronization. Instance changes require synchronization, not replay. A `REQUEST_EXPIRED` query retains its pending identity until the operator explicitly resolves it through a confirmation explaining the unknown outcome and duplicate-work risk. Resolution forgets only local pending metadata, leaves draft/history intact, and never resends or cancels service work. Initial/reopened history does not play audio. Explicit model/speech refresh admits an asynchronous inventory job; configuration saves the exact observed model/voice. Text chat does not require speech health. Type/Microphone and Text/Text+speech share one editable draft, with explicit Send after transcription. Draft revision is captured when recording starts. If the draft is unchanged, transcription appends after a newline to existing text (or fills an empty draft); repeated dictation adds to the same draft and never silently replaces typed text. Edits during capture or transcription are preserved, with the transcript exposed for explicit insertion instead. Transcription never sends automatically, and cancelling recording preserves the draft. Speech-off stops/suppresses pending/current playback without stopping microphone capture, and enabling speech again does not replay it. A microphone launch failure shows an error and returns to idle, leaving typed chat available. Answer text remains visible even if TTS, playback, or subsequent state synchronization fails. Deliberate Speak calls synthesis only, not generation.

`NativeAudio` uses fixed `/usr/bin/parecord` and `/usr/bin/paplay`, no shell/PATH lookup/plugins. It requires `pulseaudio-utils` and a PulseAudio-compatible user session (including PipeWire Pulse). Capture is bounded mono16kHz PCM16 wrapped as WAV, at most 60 seconds/2 MiB. Playback validates mono24kHz PCM16 WAV at most 60 seconds/2,880,044 bytes and uses a 65-second budget. Private transient directories/files are set to 0700/0600 through Dart stdlib `dart:ffi` and fixed Ubuntu libc descriptor operations; no new package or audio plugin is added. Native PCM travels through pipes; providers receive WAV bytes, never filesystem paths. Cleanup sends captured-child TERM, then KILL after one second and waits one more second; unconfirmed exit blocks reuse. Only the captured regular file and empty directory are deleted, without recursive traversal. Temporary audio is not chat persistence; crash cleanup is not guaranteed.

Tests inject app/audio/process seams; no real microphone, playback, provider inventory/inference or normal-host manager is used. The compiled socket fixture additionally checks the frozen app state envelope/PID, restored config and distinct instance IDs after restart, alongside existing Core regressions. All four modes and speech/ack/edit/timeout failure paths are fake evidence, not real inference or speech evidence.
